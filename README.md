用 C 从零搭一个离散事件仿真器，复现“一个执行流同时等待多个 I/O 源”这件事；在同一套语义下替换几种数据结构，比较延迟分布、公平性与过载行为。

目标不是复刻 epoll，而是把它背后的成本结构拆开，用自己的结构重新拼一遍，再用数据说明为什么这样拼。

**这是课程作业，不是生产库。** 结论以实验数据为准，不以功能完整为目标。

## 设计约定

改代码之前先读这一节，它决定了仓库里所有东西的形状。

- **语言用 C99**：缓存行为、分配次数、指针追逐必须是可见的，这是“硬件视角”的载体。
- **不依赖封装**：不链接 libevent / libuv / libev，不用语言运行时自带的事件循环。
- **真机只用于校准**：epoll / select / poll 与 strace / perf 只出现在 `real/` 和实验脚本里，不进入仿真器的执行路径。
- **确定性优先**：单线程、虚拟时钟（int64 纳秒）、固定种子；同一份配置两次运行必须逐字节一致。
- **机制与策略分离**：等待名单、就绪名单、定时器、运行队列都是可替换模块，共用一套接口；换策略不改机制。
- **报分布不报均值**：至少 p50 / p99 / p99.9 与累积分布。
- **一条命令复现**：每个实验一个入口、一个种子、一份配置哈希。
